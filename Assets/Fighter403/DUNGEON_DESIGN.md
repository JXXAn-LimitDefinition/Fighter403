# Fighter403 地牢关卡系统设计（草案）

## 1. 目标

- 一局 25–35 分钟，共 3 层。每层约 10 个房间，最后一间是 Boss。
- 同一个种子生成同一张地图、同一批敌人和同一组奖励候选。玩家在前面做了什么选择，都不会改变后面已经由种子决定的内容。
- 关卡要配合现有战斗的三个特点：规划时的时间减速、按现实时间回复的能量、6 格连招队列。

## 2. 主题：403 Forbidden

项目名里的 403 正好是 HTTP 的「拒绝访问」，现有卡牌和系统（Sandevistan、矩阵护壁、Debugger、加速迭代）也已经是赛博朋克风格。建议的设定：玩家是一个入侵程序，闯进一台拒绝访问的服务器，一层层往下打到内核。

| 层 | 名称 | 敌人风格 | Boss |
| --- | --- | --- | --- |
| 1 | 外网缓存区 | 近战敌、蜂群，教学性质 | 防火墙守卫 |
| 2 | 防火墙矩阵 | 加入射手、护盾兵，开始出现房间词条 | 审计进程 |
| 3 | 内核 | 精英混编，词条更多 | 根权限管理员 Root |

## 3. 一局的流程

开局拿到初始牌组，然后进入第 1 层。走房间、打 Boss，Boss 之后有一次层间奖励（Debugger 三选一，并回复部分生命），再进入下一层。第 3 层 Boss 打完算通关，中途生命归零就结束这一局。

## 4. 楼层结构：房间网格

推荐做成《以撒的结合》那种房间网格，而不是《杀戮尖塔》那种节点路线图：

- 战斗是俯视角实时的，每个房间正好是一块竞技场。进门锁门，清完开门。
- 地图可以回头走，玩家自己决定先去商店还是先打精英，更有「地牢」的感觉。

### 房间类型

| 类型 | 每层数量 | 内容 |
| --- | ---: | --- |
| 起点 | 1 | 没有敌人 |
| 战斗 | 5–8 | 清完后卡牌三选一，外加数据碎片 |
| 精英 | 1–2 | 更难的编成，奖励 Debugger 三选一 |
| 宝库 | 1 | 一个免费 Debugger 或一张稀有牌 |
| 商店 | 1 | 用数据碎片买牌、删牌、回血 |
| 维护站 | 0–1 | 删一张牌，或回复 30% 生命，二选一 |
| 事件 | 0–2 | 文字选择，有风险有收益 |
| 隐藏房 | 0–1 | 用相位突进撞开可疑的墙才能进入 |
| Boss | 1 | 楼层出口 |

隐藏房直接利用现有的相位突进：突进本来就会被障碍挡住（`dashObstacleMask`），给某些墙标记为可破坏，撞上去就打开。这样不用另外加炸弹之类的道具。

## 5. 敌人编成

### 基础敌人
- **近战敌**：已有，1.25 范围内前摇、造 12 点。
- **射手**（新）：远距离投射，周期 2 秒一发，每发 8 点。站地不动。
- **蜂群**（新）：一只强化近战敌，扫 1.5 范围，周期 1 秒，每次 5 点。速度快。
- **护盾兵**（新）：生命多一倍。护盾从任意方向吸收全部伤害，打破护盾的那一击也由护盾吸收，后续命中才扣生命。

### 精英敌人

精英敌人各有一个特殊机制，每个机制都逼玩家换一种排牌思路。它们和普通敌人混编出现。

| 名称 | 血量 | 机制 | 克制打法 | 出现层 |
| --- | ---: | --- | --- | --- |
| **共鸣者** | 60 | 每次被击中，场上其他敌人伤害 +25%，持续 3 秒，最多叠 3 层 | 锁定它，用落点重击或千击万斩一套带走，别用会多段命中的回旋慢慢磨 | 1–3 |
| **镜像** | 50 | 玩家每打出一张攻击牌，1 秒后它用同样的判定形状反打一次，伤害为原牌的 50% | 连招里插矩阵护壁，或者用相位突进打完就走 | 2–3 |
| **集群** | 40 ×2 | 两只成对出现。彼此距离 3 以内时都只受 50% 伤害。杀掉一只后，另一只移速 +50% | 等它们拉开距离再打，或者先用落点重击眩晕其中一只 | 2–3 |
| **分裂者** | 80 | 单次受到 20 点以上伤害就分裂成两只 40 血的小分裂者，最多分裂 2 次 | 用快速斩击等小伤害牌慢慢削，或者先分裂再用回旋一起清 | 2–3 |
| **协议** | 100 | 护盾兵升级版。护盾存在时，每秒给场上其他敌人回 3 点血 | 三角裂斩先加裂痕伤害，集中火力破盾 | 3 |

### 编成规则（种子生成）

每个战斗房间根据种子确定敌人数量和类型。初级（第 1 层）只有近战敌和蜂群，逐步混入射手、护盾兵和精英敌人。

```
第 1 层：
- 普通房：1–3 只近战敌
- 精英房：1 只共鸣者 + 2 只近战敌
- Boss：防火墙守卫（高血量近战敌 ×1，主人公生命上限 ×1.5）

第 2 层：
- 普通房：射手 1 + 近战敌 1–2，或护盾兵 1 + 蜂群 1
- 精英房：1 只镜像 / 1 组集群 / 1 只分裂者（三选一）
- Boss：审计进程（射手 ×2 + 护盾兵 ×1）

第 3 层：
- 普通房：全都是混编，更凶
- 精英房：协议 + 1–2 只小兵
- Boss：Root（护盾兵 ×1，不断召唤小蜂群）
```

## 6. 卡牌奖励

### 牌组初始化
开局玩家只有 5 张牌，不是全部 9 张。初始牌组建议：
- 快速斩击（费 1）×2
- 相位突进（费 2）×2
- 矩阵护壁（费 2）×1

这样开局能量上限 10，第一轮最多排 4 张牌，给玩家一个学习的台阶。

### 奖励池
每打完战斗房间，给玩家三选一的牌张奖励：

**基础牌**（总是在池子里）
- 重复一张手中已有的牌

**按层解锁**
- 第 1 层：快速斩击、斩击蓄势、三角裂斩
- 第 2 层：加入回旋、矩阵护壁
- 第 3 层：加入落点重击、相位突进、Sandevistan

**稀有牌**（只在宝库和精英奖励里）
- 千击万斩

每个房间奖励还有 50 数据碎片（货币）。

## 7. Debugger（遗物/词条）

### 现有
- 加速迭代：出牌期间能量回复 +100%

### 新增建议
- **硬化**：格挡衰减 -50%（即衰减变为 0.25/秒）
- **血清**：获得 Debugger 时回复 25% 生命
- **临界**：伤害 +20%
- **并行**：手牌上限从 6 增加到 7
- **缓存**：抽牌堆不用时减速时间到 0.05 倍（比锁定目标还多）

Debugger 获取机制：
- 精英房通关：三选一
- 宝库房：一个（免费）
- 层间奖励（打完 Boss）：三选一
- 商店：用 200+ 碎片买一个

### 层间奖励
打完 Boss 后，玩家选一个 Debugger（三选一），然后回复 50% 生命。如果已经有 5 个 Debugger，就改成选其中一个删掉。

## 8. 商店

在商店房里，玩家可以花数据碎片：
- 买牌：50 个碎片买一张手中还没有的牌（从奖励池选）
- 删牌：25 个碎片删一张手中的牌（永久移除）
- 回血：100 个碎片回复 30% 生命

## 9. 种子生成架构

### 伪代码流程
```
seed = user_input_or_hash(username + date)
rng = SeededRandom(seed)

for layer in [1, 2, 3]:
    dungeon[layer] = []
    
    # 房间排布
    num_rooms = 10 + rng.Next(-1, 2)  # 9–11 间
    for i in range(num_rooms):
        room_type = rng.Choice(['战斗', '战斗', '精英', '宝库', '商店', ...])
        dungeon[layer].append(room_type)
    
    # 添加 Boss
    dungeon[layer].append('Boss')
    
    # 敌人编成
    for room in dungeon[layer]:
        if room == '战斗':
            enemies = GenerateEnemies(rng, layer, difficulty='normal')
        elif room == '精英':
            enemies = GenerateEnemies(rng, layer, difficulty='elite')
    
    # 卡牌奖励池
    dungeon[layer].rewards = GenerateRewardPool(rng, layer)
    
    # 事件和隐藏房
    for event_slot in EventSlots:
        event = rng.Choice(EventPool[layer])
        dungeon[layer].append(event)

return dungeon
```

### 实现建议
- C# 类：`DungeonGenerator`，构造函数传入 `seed` 和 `layer`。
- 内部用 `System.Random(seed)` 或 Unity 的 `Random.InitState(seed)`。
- 返回序列化的关卡数据（房间列表 + 每间房的敌人/奖励列表）。
- 存储在 `ScriptableObject` 或 JSON，这样用户的本地 Debugger 和卡牌选择可以独立持久化。

## 10. 时间设计

### 现实时间 vs 游戏时间
- 敌人行为（移动、前摇冷却）用游戏时间，不受玩家规划时减速影响。
- 能量回复用现实时间，所以规划 10 秒和实际 1 秒一样回 1 点能量。
- 这意味着走廊（无战斗）期间，玩家的能量会正常回复，可以到商店时已经恢复满。

### 单间房间的平衡
目标每间房 2–4 分钟（包括规划时间）：
- 规划：1 秒（时间 0.1 倍，玩家只是选目标和排序）
- 执行：1–3 秒（时间 1 倍）
- 结算（奖励界面）：0–1 秒

整个地牢 10 间房 + 3 个 Boss × 3 层 = 39 间，每间平均 2 分钟 = 78 分钟。如果想压到 25–35 分钟，要减房间数或提速。建议每层 7–8 间房 + Boss = 8–9 间 × 3 层 = 24–27 间 × 2 分钟 = 48–54 分钟，这样第一轮运行就很快了。

## 11. 风险与收益

### 事件示例
事件是选择型的文字剧情，有风险有收益，增加重玩性。比如：

| 事件 | 选项 A | 选项 B |
| --- | --- | --- |
| 病毒代码 | +20% 伤害，-10% 格挡 | 跳过 |
| 备份陷阱 | 获得一张免费牌 | 失去 50% 生命 |
| 升级提示 | 删一张牌，回 50% 生命 | 跳过 |

## 12. 下一步实现优先级

1. **敌人类**：射手、蜂群、护盾兵（新 C# 脚本）
2. **DungeonGenerator**：种子生成房间列表
3. **房间加载系统**：根据房间类型实例化敌人
4. **奖励 UI**：打完房间后卡牌三选一界面
5. **商店 UI**：买牌、删牌、回血按钮
6. **事件系统**：文字选择和后果处理
7. **Debugger 获取**：从宝库、精英、层间奖励获得

---

**设计哲学**  
这个系统要能容纳现有的卡牌和战斗逻辑，不需要重写战斗代码。地图本身是随机的，但一旦种子确定，全部是确定的——玩家在前面的选择（买牌、删牌、拿 Debugger）会影响后续战力，而不是后续生成的房间本身。这样既有肉鸽的"奖励-选择-发展"循环，又保持了种子的可重放性。
